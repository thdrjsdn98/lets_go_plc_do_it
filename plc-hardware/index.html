01. CPU 종류와 선택 기준

📌 핵심 CPU 계열

계열특징
S7-1200엔트리~미들레인지, 소규모 자동화에 적합
S7-1500고성능, 대규모 설비·모션제어에 적합
S7-300/400레거시(구형) CPU, 주로 STEP 7 Classic 사용

1. 선택 기준

필요한 I/O 점수, 통신 포트 수, 연산 속도, 프로그램/데이터 메모리 용량을 먼저 파악한 뒤 이를 만족하는 CPU 모델을 고른다.

2. 확장성 고려

설비가 향후 커질 가능성이 있다면, 처음부터 I/O 확장 슬롯과 통신 포트가 넉넉한 상위 모델을 선택하는 것이 유지보수에 유리하다.

3. S7-1200 내에서도 등급이 나뉜다

S7-1200 안에서도 CPU 1211C(가장 작은 I/O)부터 CPU 1215C, 1217C(더 많은 I/O·아날로그 채널)까지 여러 등급이 있다. 필요한 I/O 개수를 미리 계산해두면 적정 모델을 고르기 쉽다.

4. 안전(Safety) 기능이 필요한 경우

비상정지, 안전문 등 기능안전(Functional Safety)이 필요한 설비라면 일반 CPU 대신 F-CPU(Fail-safe CPU, 예: 1215FC)를 선택해야 한다. F-CPU는 안전 관련 표준(SIL/PL)을 만족하도록 설계된 전용 모델이다.

5. CPU 선택 체크리스트

① 필요한 디지털/아날로그 I/O 개수, ② 필요한 통신 방식(PROFINET/PROFIBUS 등), ③ 안전 기능 필요 여부, ④ 향후 확장 가능성, ⑤ 예산. 이 다섯 가지를 표로 정리해두고 비교하면 CPU 선정 실수를 줄일 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 고성능·대규모 설비에 주로 사용되는 최신 지멘스 CPU 계열은?

💡 해설: S7-1500은 고성능이 필요한 대규모 설비나 모션제어에 주로 사용됩니다.

Q2. 소규모 자동화 설비에 적합한 엔트리급 최신 CPU 계열은?

💡 해설: S7-1200은 엔트리~미들레인지급으로 소규모 자동화 설비에 적합합니다.

Q3. 비상정지 등 기능안전이 필요한 설비에 사용해야 하는 CPU 종류는?

💡 해설: 기능안전이 필요한 설비에는 안전 표준을 만족하도록 설계된 F-CPU(Fail-safe CPU)를 사용해야 합니다.

Q4. CPU를 선정할 때 체크리스트에 포함하기에 가장 거리가 먼 것은?

💡 해설: CPU 선택 시 I/O 개수, 통신 방식, 안전기능, 확장성, 예산 등을 고려해야 하며 색상은 기능적 기준이 아닙니다.

02. 디바이스 추가와 하드웨어 카탈로그

1. 하드웨어 카탈로그

우측 태스크카드의 하드웨어 카탈로그에서 CPU, I/O 모듈, 통신 모듈 등을 검색·필터링해 찾을 수 있다.

2. 슬롯 배치 규칙

CPU 옆 슬롯부터 순서대로 모듈을 배치해야 하며, 모델별로 확장 가능한 슬롯 수와 위치에 제한이 있으므로 매뉴얼상의 배치 규칙을 따라야 한다.

3. 검색 팁

정확한 주문번호를 모른다면 CPU 라벨의 문자를 카탈로그 검색창에 입력해 필터링하는 방식으로 빠르게 찾을 수 있다.

4. 신호 모듈(SM)과 통신 모듈(CM)

입출력을 늘리는 신호 모듈(Signal Module, SM)과, PROFIBUS 등 추가 통신 포트를 위한 통신 모듈(Communication Module, CM)을 구분해서 카탈로그에서 찾아야 한다. 흔히 SM은 CPU 오른쪽, CM은 CPU 왼쪽에 배치하는 규칙을 가진 제품군도 있으므로 매뉴얼을 확인해야 한다.

5. 시뮬레이션으로 배치 미리보기

실제 구매 전, 카탈로그에서 모듈들을 가상으로 배치해보면서 필요한 슬롯 수와 전원 소모량을 미리 계산해볼 수 있다. 전원 모듈의 용량을 초과해 모듈을 배치하면 실제로는 정상 동작하지 않으므로 이 계산이 중요하다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 디바이스 추가시 실물 CPU와 반드시 일치시켜야 하는 항목은? (한글) (단답형)

💡 해설: 실제 CPU의 정확한 주문번호를 그대로 선택해야 다운로드시 오류가 발생하지 않습니다.

Q2. CPU 옆에 입출력 모듈을 추가할 때 참고하는 창은?

💡 해설: 하드웨어 카탈로그에서 필요한 I/O 모듈, 통신 모듈 등을 검색해 배치할 수 있습니다.

Q3. 입출력 개수를 늘리기 위해 추가하는 모듈은?

💡 해설: 신호 모듈(Signal Module, SM)은 디지털·아날로그 입출력을 확장하는 데 사용됩니다.

Q4. 모듈을 여러 개 배치하기 전에 미리 계산해야 하는 것은?

💡 해설: 전원 모듈의 용량을 초과해 모듈을 배치하면 정상 동작하지 않으므로 미리 소모 전력을 계산해야 합니다.

03. I/O 어드레싱 체계

📌 핵심 용어

기호의미
%I입력(Input) - 버튼, 센서 등 외부 신호가 들어오는 주소
%Q출력(Output) - 램프, 모터 등 외부로 나가는 신호 주소
%M내부 메모리 비트 - PLC 내부에서만 쓰는 임시 신호
%DB데이터 블록 - 변수·설정값을 구조적으로 저장

1. 비트·바이트·워드 표기

I0.0은 입력 0바이트의 0번 비트를 뜻하며, I0.0~I0.7을 묶어 IB0(바이트), 두 바이트를 묶으면 IW0(워드)로 표기한다. 출력(Q)과 메모리(M)도 동일한 표기 규칙을 따른다.

2. 아날로그 신호의 주소

디지털 신호가 0/1의 비트 단위라면, 아날로그 신호(온도·압력 센서 등)는 보통 IW(워드) 단위로 표현되며 0~27648 같은 정수 범위 값으로 변환되어 들어온다.

3. 심볼릭 이름(태그 이름) 활용

실제 프로그램에서는 I0.0처럼 절대 주소만 쓰기보다, '기동버튼_라인1'처럼 의미를 담은 심볼릭 이름(태그 이름)을 지정해서 사용하는 것이 훨씬 읽기 쉽고 유지보수하기 좋다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. I0.0, I0.1 ... I0.7을 묶어서 부르는 바이트 단위 표기는?

💡 해설: I0.0~I0.7 8개의 비트를 묶은 바이트 단위 표기는 IB0입니다.

Q2. 외부로 나가는 출력 신호(램프, 모터 등)에 사용하는 어드레스 접두사는?

💡 해설: %Q는 출력(Output), %I는 입력(Input)에 사용하는 어드레스 접두사입니다.

Q3. 온도·압력 센서 같은 아날로그 신호는 보통 어떤 단위로 표현되는가?

💡 해설: 아날로그 신호는 보통 워드(IW) 단위의 정수 범위 값으로 변환되어 PLC에 들어옵니다.

Q4. I0.0 대신 '기동버튼_라인1'처럼 의미 있는 이름을 붙여 쓰는 것을 무엇이라 하는가?

💡 해설: 의미를 담은 이름을 심볼릭 이름(태그 이름)이라 하며, 프로그램의 가독성을 크게 높여줍니다.

04. PG/PC 인터페이스와 온라인 액세스

1. 온라인 액세스 설정

PC와 PLC를 연결하려면 온라인 액세스(Online access) 메뉴에서 실제로 케이블이 꽂힌 네트워크 어댑터를 선택해야 한다.

2. 통신 방식

요즘 CPU는 대부분 PROFINET(이더넷) 방식으로 연결하며, PC의 IP 대역과 CPU의 IP 주소가 같은 서브넷에 있어야 정상적으로 통신된다.

3. 여러 어댑터가 있을 때 주의점

노트북에는 유선랜, 무선랜, 가상 어댑터(VPN 등) 여러 개가 동시에 존재하는 경우가 많다. 실제로 PLC와 케이블로 연결된 어댑터를 정확히 골라야 하며, 잘못된 어댑터를 선택하면 '검색되는 디바이스 없음' 오류가 흔히 발생한다.

4. 접근 가능한 노드 검색

온라인 액세스 화면에서 '접근 가능한 디바이스 검색(Accessible devices)' 버튼을 누르면, 현재 네트워크에 연결된 PLC들이 자동으로 검색되어 목록에 나타난다. IP 주소를 잘 모를 때 특히 유용하다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. PC와 PLC를 실제로 연결하기 위해 선택해야 하는 설정은?

💡 해설: 실제로 케이블이 꽂힌 네트워크 어댑터를 온라인 액세스에서 선택해야 통신이 가능합니다.

Q2. 최신 지멘스 CPU가 PC와 통신할 때 주로 사용하는 물리적 연결 방식은?

💡 해설: 요즘 CPU는 대부분 PROFINET(이더넷) 방식으로 PC와 통신합니다.

Q3. 노트북에 여러 네트워크 어댑터가 있을 때 흔히 발생하는 문제는?

💡 해설: 실제 PLC와 연결된 어댑터가 아닌 다른 어댑터를 선택하면 디바이스가 검색되지 않는 문제가 흔히 발생합니다.

Q4. IP 주소를 잘 모를 때 네트워크상의 PLC를 찾는 데 유용한 기능은?

💡 해설: 접근 가능한 디바이스 검색 기능으로 네트워크에 연결된 PLC들을 자동으로 찾을 수 있습니다.

05. IP 주소·서브넷 설정

1. IP 주소 지정

하드웨어 구성 화면에서 CPU를 클릭하면 인스펙터 창의 속성(Properties) → 일반(General) → 이더넷 주소에서 IP 주소·서브넷 마스크를 지정할 수 있다.

2. 주소 충돌 주의

같은 네트워크에 여러 CPU가 있다면 서로 겹치지 않는 IP를 부여해야 하며, 충돌 시 통신 오류나 다운로드 실패가 발생할 수 있다.

3. 서브넷 마스크의 의미

서브넷 마스크(예: 255.255.255.0)는 IP 주소 중 어디까지가 네트워크를 구분하는 부분인지를 나타낸다. PC와 CPU의 서브넷 마스크가 다르면 같은 대역처럼 보여도 통신이 안 될 수 있다.

4. 고정 IP 관리 팁

현장에서는 나중에 설비를 추가하거나 교체할 때를 대비해, IP 주소를 문서(배치도)로 정리해두는 것이 유지보수에 큰 도움이 된다. IP가 겹치는 사고는 현장에서 실제로 자주 발생하는 실수 중 하나다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. CPU의 IP주소를 설정하는 위치는?

💡 해설: 인스펙터 창의 속성(Properties) 탭 안 이더넷 주소 항목에서 IP주소를 설정합니다.

Q2. 같은 네트워크의 여러 CPU에 절대 겹치면 안 되는 값은?

💡 해설: 같은 네트워크 안의 여러 CPU는 서로 다른 IP 주소를 가져야 통신 충돌이 발생하지 않습니다.

Q3. 서브넷 마스크의 역할은 무엇인가?

💡 해설: 서브넷 마스크는 IP 주소 중 어디까지가 네트워크 구분에 사용되는지를 나타냅니다.

06. PROFINET / PROFIBUS 네트워크 개요

1. PROFINET

이더넷 기반의 최신 지멘스 산업용 통신 프로토콜로, 실시간성을 지원하며 S7-1200/1500에서 표준으로 사용된다.

2. PROFIBUS

주로 S7-300/400 세대와 함께 쓰이던 구형 시리얼 기반 필드버스로, 최근에는 PROFINET으로 전환되는 추세다.

3. 토폴로지(배선 구조)

PROFINET은 스타형, 라인형, 링형 등 다양한 네트워크 구조(토폴로지)를 지원해 배선 방식에 유연성이 있는 반면, PROFIBUS는 전통적으로 버스(라인)형 배선이 기본이었다.

4. 두 프로토콜 간 연동

구형 PROFIBUS 장비를 최신 PROFINET 네트워크에 연결해야 할 때는 PROFINET/PROFIBUS 게이트웨이(변환 장치)를 사용해 두 프로토콜을 연동시킬 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

💡 해설: PROFINET은 이더넷 기반의 최신 산업용 통신 프로토콜로 실시간성을 지원합니다.

Q2. 주로 S7-300/400 세대와 함께 쓰이던 구형 시리얼 기반 필드버스는?

Q3. PROFINET이 지원하는 네트워크 배선 구조(토폴로지)로 옳은 것은?

💡 해설: PROFINET은 스타형, 라인형, 링형 등 다양한 토폴로지를 지원해 배선에 유연성이 있습니다.

💡 해설: 두 프로토콜 간에는 변환 장치인 게이트웨이를 사용해 연동할 수 있습니다.

07. 다운로드와 하드웨어 불일치 문제

1. 흔한 오류 원인

다운로드시 '하드웨어 불일치' 오류는 프로젝트에 설정된 CPU 주문번호나 펌웨어 버전이 실제 CPU와 다를 때 자주 발생한다.

2. 해결 방법

온라인 진단(Online & Diagnostics)에서 실제 연결된 CPU의 주문번호·펌웨어 버전을 확인한 뒤, 프로젝트의 하드웨어 구성과 대조해 일치시킨다.

3. 펌웨어 버전 불일치 대응

펌웨어 버전이 프로젝트보다 낮으면 펌웨어 업데이트가 필요할 수 있고, 반대로 프로젝트 설정을 실제 CPU의 펌웨어 버전에 맞춰 낮추는 방법도 있다. 상황에 따라 더 간단한 쪽을 선택한다.

4. 다운로드 전 최종 점검 리스트

① 올바른 네트워크 어댑터 선택, ② CPU가 STOP 모드인지 확인(다운로드는 보통 STOP 상태에서 안전), ③ 하드웨어 구성과 실제 배치가 일치하는지, 이 세 가지를 다운로드 직전에 습관적으로 확인하면 문제를 크게 줄일 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 다운로드시 '하드웨어 불일치' 오류가 자주 발생하는 원인은?

💡 해설: 프로젝트에 설정된 CPU 정보와 실제 하드웨어가 일치하지 않을 때 하드웨어 불일치 오류가 발생합니다.

Q2. 실제 연결된 CPU의 정보(주문번호, 펌웨어 등)를 확인할 수 있는 기능은?

💡 해설: 온라인 진단(Online & Diagnostics) 기능으로 실제 연결된 CPU의 상세 정보를 확인할 수 있습니다.

Q3. 실제 CPU의 펌웨어 버전이 프로젝트 설정보다 낮을 때 취할 수 있는 조치는?

💡 해설: 펌웨어를 업데이트하거나 프로젝트의 설정 버전을 실제 CPU에 맞춰 조정하는 방법이 있습니다.

Q4. 다운로드 직전에 확인하면 좋은 항목이 아닌 것은?

💡 해설: 글꼴 종류는 다운로드와 무관하며, 어댑터·CPU 모드·하드웨어 구성 일치 여부가 실질적인 점검 항목입니다.

08. PLCSIM 시뮬레이션 활용

1. PLCSIM이란

지멘스가 제공하는 PLCSIM(S7-PLCSIM) 시뮬레이터는 실제 CPU 없이도 PC 안에 가상 CPU를 만들어 프로그램을 다운로드·테스트할 수 있게 해준다.

2. 활용 방법

PLCSIM에서는 와치 테이블(Watch table)을 이용해 특정 입력 비트를 강제로 On/Off 시켜가며, 실제 배선 없이도 로직이 의도대로 동작하는지 검증할 수 있다.

3. PLCSIM Advanced

더 고급 기능이 필요하다면 PLCSIM Advanced를 통해 가상 네트워크 통신, API 연동 등 확장된 시뮬레이션 환경을 사용할 수도 있다.

4. 시뮬레이션의 한계

PLCSIM은 로직(프로그램) 검증에는 매우 유용하지만, 실제 아날로그 신호의 노이즈, 배선 저항, 기계적 지연 같은 물리적 요소까지 완벽히 재현하지는 못한다. 따라서 시뮬레이션에서 검증한 로직도 실제 하드웨어에서 다시 한번 확인하는 과정이 필요하다.

5. 실무 활용 시나리오

현장에 실제 설비가 아직 설치되지 않은 초기 개발 단계에서, PLCSIM으로 기본 로직을 미리 완성해두면 실제 설비가 도착했을 때 다운로드 후 미세 조정만으로 빠르게 가동할 수 있어 개발 기간을 크게 단축할 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 실제 하드웨어 없이 PC에서 가상 CPU를 만들어 테스트하는 지멘스 시뮬레이터 이름은? (영문) (단답형)

💡 해설: PLCSIM(S7-PLCSIM)은 실제 CPU 없이도 PC에서 가상 CPU를 만들어 프로그램을 테스트할 수 있는 지멘스의 시뮬레이터입니다.

Q2. PLCSIM/실제 PLC 모두에서 특정 비트 값을 강제로 켜고 끄며 로직을 확인할 때 사용하는 도구는?

💡 해설: 와치 테이블(Watch table)을 사용하면 특정 비트를 강제로 On/Off하며 로직 동작을 확인할 수 있습니다.

Q3. PLCSIM 시뮬레이션의 한계로 옳은 것은?

💡 해설: PLCSIM은 로직 검증에는 유용하지만 실제 물리적 요소까지 완벽히 재현하지는 못합니다.

Q4. 실제 설비가 도착하기 전 PLCSIM을 활용하는 이유는?

💡 해설: 설비 도착 전에 기본 로직을 PLCSIM으로 미리 완성해두면 실제 가동까지의 기간을 크게 단축할 수 있습니다.
