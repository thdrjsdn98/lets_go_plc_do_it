01. TIA Portal이란?

📌 핵심 용어

용어의미
TIA PortalPLC·HMI·드라이브를 하나의 SW에서 다루는 통합 엔지니어링 플랫폼
S7-1200/1500최신 세대 CPU, TIA Portal로 프로그래밍
S7-300/400구형 CPU, 주로 STEP 7 Classic(SIMATIC Manager)로 프로그래밍
TIATotally Integrated Automation의 약자

1. TIA Portal 개요

지멘스의 통합 엔지니어링 소프트웨어로, S7-1200·S7-1500 PLC, ET200 원격 I/O, HMI 터치패널, SINAMICS 드라이브를 하나의 프로젝트 안에서 함께 설정·프로그래밍한다. 'TIA'는 Totally Integrated Automation(완전히 통합된 자동화)의 약자로, 지멘스가 자동화 제품군 전체를 하나의 철학으로 묶어 부르는 이름이기도 하다.

2. 왜 예전엔 여러 소프트웨어를 따로 썼나

TIA Portal 이전에는 PLC 프로그래밍용 STEP 7, HMI 화면 제작용 WinCC, 드라이브 설정용 STARTER 등을 각각 따로 실행해야 했다. 이 방식은 태그(주소)를 프로그램마다 따로 입력해야 하고, 한 프로그램에서 바꾼 이름이 다른 프로그램에는 자동으로 반영되지 않아 실수가 잦았다.

3. 이름이 헷갈리는 이유

TIA Portal 안에서 PLC를 프로그래밍하는 파트의 이름이 'STEP 7'이다. 그래서 '구형 STEP 7 Classic'과 'TIA Portal 안의 STEP 7'을 혼동하기 쉬운데, 전자는 별도 프로그램(SIMATIC Manager), 후자는 TIA Portal에 내장된 기능이라는 점을 구분해야 한다.

4. 통합환경의 장점

PLC 태그를 HMI 화면에서 그대로 끌어다 쓸 수 있고, 진단 정보가 하나의 창에서 통합 관리되며, 프로젝트 파일이 하나로 묶여 관리가 쉬워진다. 또한 여러 CPU와 HMI, 드라이브가 하나의 프로젝트 트리 안에 있으므로 전체 설비의 구성을 한눈에 파악하기도 좋다.

5. TIA Portal이 지원하는 제품군 예시

분야대표 제품
PLCS7-1200, S7-1500 (일부 S7-300/400 연동)
HMIBasic Panel, Comfort Panel 등 터치패널
드라이브SINAMICS 계열 인버터
원격 I/OET200 시리즈

💡 실무 팁

처음 배울 때는 'TIA Portal = PLC 프로그램만 짜는 곳'이라고 오해하기 쉬운데, 실제로는 설비 전체의 엔지니어링 데이터가 모이는 하나의 큰 그릇이라고 이해하면 이후 단원들의 구조가 훨씬 쉽게 이해된다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. TIA Portal이 통합적으로 다루는 대상이 아닌 것은?

💡 해설: TIA Portal은 PLC, HMI, 드라이브를 통합 엔지니어링하는 플랫폼이며 스마트폰 앱 개발과는 무관합니다.

Q2. S7-1200/1500처럼 최신 CPU 계열의 프로그래밍에 쓰이는 지멘스 통합 SW 이름은? (영문) (단답형)

💡 해설: TIA Portal은 최신 지멘스 CPU 계열의 통합 엔지니어링 소프트웨어입니다.

Q3. 'TIA'라는 이름이 뜻하는 것은?

💡 해설: TIA는 'Totally Integrated Automation(완전히 통합된 자동화)'의 약자입니다.

Q4. TIA Portal 이전 방식(개별 소프트웨어 사용)의 단점으로 옳은 것은?

💡 해설: 개별 소프트웨어를 따로 쓰면 태그(주소) 동기화가 안 되어 실수가 잦아지는 것이 대표적 단점이었습니다.

02. 설치와 라이선스 개요

1. 설치 시 고려사항

TIA Portal은 상당한 디스크 용량과 메모리를 요구하는 무거운 소프트웨어다. 원활한 사용을 위해 SSD 사용과 충분한 메모리 확보가 권장되며, 여러 버전을 동시에 설치(멀티버전 공존)할 수 있어 예전 프로젝트도 계속 열어볼 수 있다.

2. 라이선스 방식

TIA Portal/STEP 7은 일반적으로 라이선스 키(License Key)를 USB 메모리나 PC에 저장해 인증하는 방식을 사용한다. 정식 구매 전에는 트라이얼(체험판)로 제한된 기간 사용할 수 있는 옵션도 제공된다.

3. 제품 등급 (Basic / Professional)

제품지원 범위
STEP 7 BasicS7-1200 전용
STEP 7 ProfessionalS7-1200 / S7-1500 / S7-300 / S7-400 등 폭넓게 지원
처음 시작할 CPU 종류에 맞춰 필요한 제품 등급을 선택해야 한다.

4. 라이선스 관리 도구

지멘스는 Automation License Manager라는 별도 도구로 PC에 설치된 여러 라이선스를 조회·이전·백업할 수 있게 해준다. PC를 교체하거나 재설치할 때는 이 도구로 라이선스를 먼저 옮겨두는 것이 안전하다.

5. 설치 실패를 줄이는 팁

설치 도중 오류가 잦은 편이라, ① 백신 프로그램을 잠시 끄고, ② 관리자 권한으로 설치 프로그램을 실행하고, ③ 설치 경로에 한글이나 특수문자가 없는 폴더를 지정하는 것이 문제를 줄이는 데 도움이 된다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. S7-1200만 프로그래밍 가능한 하위 등급 제품은?

💡 해설: STEP 7 Basic은 S7-1200 전용이며, S7-1500/300/400까지 다루려면 STEP 7 Professional이 필요합니다.

Q2. TIA Portal 라이선스 인증에 흔히 사용되는 방식은?

💡 해설: TIA Portal/STEP 7은 일반적으로 라이선스 키를 통해 인증합니다.

Q3. PC에 설치된 라이선스를 조회·이전·백업할 때 사용하는 지멘스 도구는?

💡 해설: Automation License Manager는 라이선스를 조회·이전·백업하는 데 사용하는 지멘스의 관리 도구입니다.

Q4. 설치 오류를 줄이기 위한 팁으로 적절하지 않은 것은?

💡 해설: 설치 경로에 한글이나 특수문자가 있으면 오히려 설치 오류가 잦아질 수 있어 피하는 것이 좋습니다.

03. Portal 뷰 vs 프로젝트 뷰

1. Portal 뷰

새 프로젝트 시작, 디바이스 구성, PLC 프로그래밍, 시각화(HMI) 구성, 온라인&진단, 옵션 설정 등 큰 작업 메뉴를 아이콘으로 골라 들어가는 초기 화면이다.

2. 프로젝트 뷰

실제로 하드웨어를 배치하고 래더 프로그램을 작성하는 본격적인 작업 화면이다. 프로젝트 트리, 작업영역, 인스펙터창, 태스크카드가 모두 이 화면에 배치된다.

3. 뷰 전환

Portal 뷰 좌측 하단의 '프로젝트 뷰로 전환' 링크를 클릭하면 이동하며, 프로젝트 뷰에서도 좌측 하단에서 다시 Portal 뷰로 돌아갈 수 있다.

4. 어느 화면부터 시작해야 할까

초보자는 Portal 뷰의 메뉴를 하나씩 눌러보며 흐름을 익히는 것이 도움이 되지만, 익숙해질수록 프로젝트 뷰에서 바로 작업하는 것이 훨씬 빠르다. 실무자 대부분은 새 프로젝트를 만든 직후에만 Portal 뷰를 잠깐 쓰고, 이후 작업은 계속 프로젝트 뷰에서 진행한다.

5. Portal 뷰의 주요 메뉴 목록

메뉴기능
디바이스 구성(Devices & networks)CPU·모듈 추가 및 네트워크 설정
PLC 프로그래밍블록 작성 및 편집
시각화 구성HMI 화면 제작
온라인 & 진단실제 하드웨어 상태 확인
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. Portal 뷰에서 프로젝트 뷰로 전환하는 링크는 화면 어디에 있는가?

💡 해설: Portal 뷰 좌측 하단의 '프로젝트 뷰로 전환' 링크를 통해 이동합니다.

Q2. 실제 하드웨어 배치와 래더 프로그래밍이 이루어지는 뷰의 이름은? (한글) (단답형)

💡 해설: 프로젝트 뷰는 하드웨어 구성과 프로그램 작성이 이루어지는 본격적인 작업 화면입니다.

Q3. 실무자들이 대체로 Portal 뷰를 사용하는 시점은?

💡 해설: 익숙해질수록 대부분의 작업은 프로젝트 뷰에서 이루어지고, Portal 뷰는 초반에만 활용하는 경우가 많습니다.

Q4. Portal 뷰에서 HMI 화면을 제작할 때 선택하는 메뉴는?

💡 해설: 시각화 구성 메뉴에서 HMI 화면(터치패널 화면)을 제작합니다.

04. 화면 구성 상세

1. 프로젝트 트리

CPU, 프로그램 블록, 태그표 등 프로젝트의 모든 구성요소가 폴더 형태로 표시되는 좌측 패널이다. 트리를 펼치면 프로그램 블록 / PLC 태그 / PLC 데이터 타입 / 감시 및 강제 테이블 등 세부 폴더가 나타난다.

2. 인스펙터 창

선택한 개체의 속성(Properties), 컴파일/온라인 정보(Info), 진단(Diagnostics) 3가지 탭으로 구성되며, 우측 하단에 위치한다.

3. 태스크 카드

명령어 목록, 즐겨찾기(Favorites), 라이브러리, 하드웨어 카탈로그 등을 드래그&드롭으로 꺼내 쓰는 우측 패널이다. 여러 개의 태스크카드 탭을 세로로 접었다 펼 수 있다.

4. 정보창(Info window)

화면 하단에 위치하며, 컴파일 시 발생한 오류·경고·정보 메시지를 확인할 수 있다. 빨간 X는 오류, 노란 느낌표는 경고를 의미하며, 메시지를 더블클릭하면 해당 오류가 발생한 위치로 바로 이동한다.

5. 작업영역(에디터)

선택한 블록의 내용이 실제로 표시·편집되는 중앙 영역이다. 프로그램 블록을 열면 LAD(래더), FBD, STL 등 원하는 편집 언어로 전환해서 볼 수 있는 경우가 많다.

💡 실무 팁 - 화면 배치 저장하기

패널의 위치나 크기를 내가 편한 대로 바꿔둔 뒤, 이 배치를 유지하고 싶다면 별도로 저장해둘 수 있는 기능이 있다. 매번 창을 재배치하는 수고를 줄일 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 컴파일 오류·경고 메시지를 확인할 수 있는 창은?

💡 해설: 정보창(Info window)은 화면 하단에서 컴파일 오류/경고/정보 메시지를 보여줍니다.

Q2. 선택한 개체(예: CPU)의 속성(IP주소 등)을 편집하는 곳은?

💡 해설: 인스펙터 창의 속성(Properties) 탭에서 선택한 개체의 세부 설정을 편집합니다.

Q3. 정보창에서 오류 메시지를 더블클릭하면 어떤 일이 일어나는가?

💡 해설: 오류 메시지를 더블클릭하면 해당 오류가 발생한 네트워크나 블록 위치로 바로 이동해줍니다.

Q4. PLC 태그, 데이터 타입, 감시 테이블 등이 폴더 형태로 표시되는 패널은?

💡 해설: 프로젝트 트리에는 CPU, 프로그램 블록, 태그표 등 프로젝트의 모든 구성요소가 폴더 형태로 표시됩니다.

05. 새 프로젝트 만들기 & 디바이스 추가

1. 새 프로젝트 생성

Portal 뷰의 '새 프로젝트 시작'에서 프로젝트 이름과 저장 경로를 지정하면 빈 프로젝트가 만들어진다. 프로젝트 이름은 나중에 여러 프로젝트를 구분해야 할 때를 대비해 설비명·라인명을 포함해 짓는 것이 좋다.

2. 디바이스 추가

프로젝트 트리에서 '새 디바이스 추가'를 선택해 CPU를 고른다. 이때 실제 PLC 본체의 정확한 주문번호(order number)를 그대로 선택해야 나중에 다운로드가 정상적으로 이루어진다.

3. 카탈로그에서 CPU 찾는 방법

정확한 주문번호를 모른다면, CPU 본체 옆면에 붙은 라벨을 사진으로 찍어두고 하드웨어 카탈로그 검색창에 모델명 일부를 입력해 필터링하는 방식으로 찾을 수 있다.

4. 프로젝트 라이브러리 vs 전역 라이브러리

프로젝트 라이브러리는 현재 프로젝트 안에서만 쓰이고, 전역 라이브러리(Global library)는 여러 프로젝트에서 공통으로 재사용할 블록·화면을 저장해두는 곳이다. 회사에서 표준화된 로직(예: 표준 모터 제어 FB)을 전역 라이브러리로 만들어두면 여러 프로젝트에서 그대로 가져다 쓸 수 있다.

5. 자주 하는 실수

①비슷해 보이는 CPU 모델을 대충 선택 → 다운로드 오류. ②저장 경로에 특수문자·너무 긴 경로 사용 → 파일 접근 오류. ③프로젝트 이름을 임시로 짓고 나중에 안 바꿈 → 나중에 여러 프로젝트가 섞여 헷갈림. 이 세 가지만 주의해도 초반 실수를 크게 줄일 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 디바이스 추가시 반드시 실물 CPU와 일치시켜야 하는 항목은? (한글) (단답형)

💡 해설: 실제 CPU의 정확한 주문번호를 선택해야 다운로드 시 하드웨어 불일치 오류를 막을 수 있습니다.

Q2. 여러 프로젝트에서 재사용할 블록을 저장해두는 곳은?

💡 해설: 전역 라이브러리(Global library)는 여러 프로젝트에서 공통으로 재사용할 블록·화면을 저장합니다.

Q3. 정확한 CPU 주문번호를 모를 때 확인할 수 있는 가장 확실한 방법은?

💡 해설: CPU 본체 측면에 붙은 라벨에서 정확한 주문번호를 확인하는 것이 가장 확실한 방법입니다.

Q4. 새 프로젝트를 만들 때 프로젝트 이름을 짓는 좋은 방법은?

💡 해설: 여러 프로젝트를 구분하기 쉽도록 설비명·라인명을 포함해 이름을 짓는 것이 실무에서 유리합니다.

06. 프로그램 블록의 종류 (OB/FC/FB/DB)

📌 핵심 용어

블록특징
OB (Organization Block)실행 진입점. OB1은 PLC가 RUN 중 반복 실행하는 메인 프로그램
FC (Function)반환값은 있으나 자체 메모리(상태)가 없는 코드 블록
FB (Function Block)인스턴스 DB를 가져 상태를 스캔 사이클 간에도 유지
DB (Data Block)변수·설정값을 저장하는 데이터 영역

1. OB1과 메인 사이클

PLC는 전원이 켜지면 OB1(메인 프로그램)을 계속 반복 실행한다. 다른 FC/FB는 보통 OB1 안에서 호출되는 구조로 설계한다.

2. FC와 FB의 차이

FC는 매번 새로 계산만 하고 끝나는 '계산기' 같은 존재이고, FB는 자신만의 인스턴스 DB를 가지고 있어 이전 스캔의 상태(예: 타이머 경과시간)를 기억할 수 있다.

3. 다른 종류의 OB도 있다

OB1 외에도 OB100(시작 OB, PLC가 STOP→RUN될 때 한 번만 실행), OB35(주기적 인터럽트 OB, 일정 시간마다 실행), 에러 처리용 OB 등 다양한 종류가 있다. 초급 단계에서는 OB1만 알아도 충분하지만, 시작 시 한 번만 할 일이 있다면 OB100을 활용할 수 있다는 것 정도는 알아두면 좋다.

4. 글로벌 DB와 인스턴스 DB

글로벌 DB는 특정 블록에 종속되지 않고 프로그램 어디서든 접근 가능한 데이터 저장소이고, 인스턴스 DB는 특정 FB 호출 하나에 전용으로 딸려있는 데이터 저장소다. 예를 들어 같은 FB를 3번 호출하면 인스턴스 DB도 3개가 생겨 서로 독립적으로 상태를 유지한다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 상태(값)를 스캔 사이클 사이에도 유지해야 할 때 사용하는 코드 블록은?

💡 해설: FB(Function Block)는 인스턴스 DB를 가지므로 스캔 사이클 사이에도 상태를 유지할 수 있습니다.

Q2. PLC가 RUN 모드에서 반복 실행하는 메인 프로그램이 담기는 블록은?

💡 해설: OB1은 PLC가 전원이 켜진 뒤 반복 실행하는 메인 프로그램(Organization Block)입니다.

Q3. PLC가 STOP에서 RUN으로 전환될 때 딱 한 번만 실행되는 OB는?

💡 해설: OB100은 시작(Startup) OB로, PLC가 STOP에서 RUN으로 바뀔 때 한 번만 실행됩니다.

Q4. 같은 FB를 3번 호출하면 인스턴스 DB는 몇 개 생기는가?

💡 해설: 각 FB 호출마다 전용 인스턴스 DB가 별도로 생성되어 서로 독립적으로 상태를 유지합니다.

07. 컴파일·다운로드·모니터링

1. 컴파일

프로그램 작성 후 컴파일(Compile)을 실행하면 문법·주소 오류를 점검한다. 정보창의 필터 버튼(오류/경고/정보)으로 원하는 메시지만 골라 볼 수 있다.

2. 다운로드

컴파일이 성공하면 다운로드(Download)로 실제 CPU(또는 PLCSIM)에 프로그램을 전송한다. 온라인 액세스에서 올바른 네트워크 어댑터가 선택되어 있어야 한다.

3. 다운로드 대화상자에서 확인할 점

다운로드 진행 중 나타나는 대화상자에서는 연결된 CPU의 주소·모델·현재 동작 상태가 표시된다. 잘못된 CPU에 실수로 다운로드하지 않도록 이 정보를 꼭 확인하는 습관이 중요하다.

4. 온라인 모니터링

다운로드 후 모니터링 켜기(Monitoring on/off) 버튼을 누르면 실제 접점·코일의 통전 상태를 색상(보통 초록색)으로 실시간 확인할 수 있다.

5. RUN/STOP 전환

CPU를 RUN 모드로 전환해야 실제로 로직이 반복 실행된다. STOP 모드에서는 프로그램이 실행되지 않으므로, 다운로드 후 RUN으로 전환하는 것을 잊지 않아야 한다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 컴파일 결과 창에서 빨간색 X로 표시되는 항목은?

💡 해설: 빨간 X는 오류(Error), 노란 느낌표는 경고(Warning)를 나타냅니다.

Q2. 온라인 모니터링 시 통전 중인 접점/코일이 일반적으로 표시되는 색은? (한글) (단답형)

💡 해설: 온라인 모니터링에서는 통전(참) 상태의 접점·코일이 보통 초록색으로 강조 표시됩니다.

Q3. 다운로드 후 실제로 로직이 반복 실행되게 하려면 CPU를 어떤 모드로 전환해야 하는가?

💡 해설: STOP 모드에서는 프로그램이 실행되지 않으므로, 다운로드 후 RUN 모드로 전환해야 합니다.

Q4. 다운로드 대화상자에서 확인해야 할 정보로 가장 적절한 것은?

💡 해설: 잘못된 CPU에 다운로드하는 실수를 막기 위해 연결된 CPU의 정보를 꼭 확인해야 합니다.

08. 프로젝트 관리와 팀 협업

1. 저장과 아카이브

작업 중간중간 Ctrl+S로 저장하는 것은 기본이고, 프로젝트 전체를 하나의 압축 파일로 백업/이동하려면 아카이브(Archive) 기능을 사용한다.

2. 버전관리 팁

정기적으로 아카이브 파일을 날짜별로 백업해두면, 문제가 생겼을 때 이전 버전으로 되돌릴 수 있어 실무에서 매우 중요한 습관이다. 파일명에 날짜와 간단한 변경 내용을 함께 적어두면(예: 20260101_모터로직수정.zap) 나중에 찾기 쉽다.

3. 팀 협업 - Multiuser Engineering

TIA Portal의 옵션 기능인 Multiuser Engineering을 사용하면 여러 엔지니어가 같은 프로젝트의 서로 다른 부분을 동시에 작업할 수 있다(대규모 프로젝트에서 유용).

4. 프로젝트 비교 기능

두 버전의 프로젝트에서 무엇이 달라졌는지 비교해주는 버전 비교(Compare) 기능도 제공되어, 여러 사람이 수정한 내용을 검토할 때 유용하게 쓸 수 있다.

5. 문서화 습관

프로그램 안에 주석(Comment)을 충실히 남기고, 태그 이름도 의미를 알 수 있게(예: I0.0 대신 '기동버튼_라인1') 지어두면, 나중에 다른 사람이 유지보수할 때 훨씬 수월해진다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. TIA Portal 프로젝트를 통째로 압축해 백업/이동할 때 사용하는 기능은?

💡 해설: 아카이브(Archive) 기능으로 프로젝트 전체를 하나의 압축 파일로 백업·이동할 수 있습니다.

Q2. 여러 엔지니어가 동시에 하나의 프로젝트를 작업할 수 있게 해주는 TIA Portal 기능은?

💡 해설: Multiuser Engineering은 여러 사용자가 동시에 하나의 프로젝트를 나누어 작업할 수 있게 해주는 옵션 기능입니다.

Q3. 두 버전의 프로젝트에서 달라진 부분을 확인할 때 사용하는 기능은?

💡 해설: 버전 비교(Compare) 기능으로 두 프로젝트 버전 사이의 차이점을 확인할 수 있습니다.

Q4. 유지보수를 쉽게 하기 위한 좋은 습관으로 가장 적절한 것은?

💡 해설: 의미 있는 태그 이름과 충실한 주석은 다른 사람이 나중에 프로그램을 이해하고 유지보수하는 데 큰 도움이 됩니다.
