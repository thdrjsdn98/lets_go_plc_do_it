01. 접점 - A접점 / B접점

1. A접점(Normally Open)

평소엔 끊어져 있다가 해당 비트가 1이 되면 통전되는 접점이다. 기동버튼처럼 '눌렀을 때 신호를 보내고 싶은' 경우에 사용한다.

2. B접점(Normally Closed)

평소엔 통전되어 있다가 해당 비트가 1이 되면 끊어지는 접점이다. 정지버튼처럼 '눌렀을 때 회로를 끊고 싶은' 경우에 자주 사용한다.

3. 선택 기준

'이 신호가 켜지면 통전시키고 싶다' → A접점, '이 신호가 켜지면 차단하고 싶다' → B접점, 이 기준만 기억해도 대부분의 상황에서 올바르게 고를 수 있다.

4. 여러 접점의 조합 - 직렬(AND)과 병렬(OR)

접점을 직렬로 연결하면 AND 조건(둘 다 참이어야 통전), 병렬로 연결하면 OR 조건(둘 중 하나만 참이어도 통전)이 된다. 복잡한 조건도 이 두 가지 조합만으로 대부분 표현할 수 있다.

5. 자주 하는 실수

정지버튼을 A접점으로 잘못 연결하면, 평소엔 회로가 끊긴 상태이고 버튼을 눌러야만 통전되어 버려 '정지'가 아니라 '기동' 역할을 하게 된다. 접점 종류를 헷갈리면 정반대로 동작하므로 각별히 주의해야 한다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 평소 열려있다가 조건이 참이 되면 닫히는(통전되는) 접점은?

💡 해설: A접점(Normally Open)은 평소 열려 있다가 조건이 참이 되면 통전됩니다.

Q2. 정지버튼처럼 '눌리면 회로를 끊고 싶은' 경우 주로 사용하는 접점은?

💡 해설: B접점(Normally Closed)은 평소 통전 상태이다가 조건이 참이 되면 회로를 끊는 데 사용됩니다.

Q3. 두 접점을 직렬로 연결했을 때의 논리적 의미는?

💡 해설: 접점을 직렬로 연결하면 AND 조건이 되어 두 조건이 모두 참이어야 통전됩니다.

Q4. 정지버튼을 실수로 A접점으로 연결하면 어떤 문제가 생기는가?

💡 해설: 정지버튼을 A접점으로 연결하면 평소 끊긴 상태이다가 눌러야 통전되어, 의도와 반대로 동작하게 됩니다.

02. 코일과 SET / RESET

1. 일반 코일 ( = )

앞의 조건이 참인 그 스캔 동안만 출력이 ON되고, 조건이 꺼지면 즉시 OFF된다.

2. SET(S) / RESET(R)

SET(S) 코일은 한 번 조건이 참이 되면 이후 조건이 꺼져도 출력이 계속 ON을 유지하며, RESET(R) 명령이 실행되어야 비로소 OFF된다.

3. 실행 순서의 중요성

SET과 RESET 조건이 같은 스캔에서 동시에 참이 되면, 일반적으로 프로그램상 나중에(아래쪽에) 배치된 명령이 최종 결과를 결정한다. 그래서 정지(RESET) 로직을 기동(SET) 로직보다 아래에 두는 것이 안전하다.

4. 부정(Negate) 접점

일부 편집기에서는 접점 앞에 NOT 표시(부정)를 붙여 조건을 반전시킬 수도 있다. B접점과 비슷한 효과를 내지만, NOT은 이미 만들어진 논리식 전체를 반전시킬 때 사용하는 경우가 많다는 차이가 있다.

5. 코일을 중복 사용하면 안 되는 이유

같은 출력(예: Q0.0)을 여러 개의 일반 코일로 중복 사용하면, 마지막에 실행된 네트워크의 결과가 이전 결과를 덮어써서 예상치 못한 동작이 발생할 수 있다. 이런 실수를 '다중 코일 할당(Multiple coil assignment)'이라 부르며, TIA Portal은 컴파일시 경고를 띄워주는 경우가 많다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 조건이 꺼지면 즉시 출력도 꺼지는 일반 코일 기호는?

💡 해설: 일반 코일(=)은 조건이 참인 동안만 출력이 ON되고 조건이 꺼지면 즉시 OFF됩니다.

Q2. SET과 RESET 코일이 같은 스캔에서 동시에 실행 조건이 되면, 최종 상태를 결정하는 요소는?

💡 해설: 일반적으로 프로그램에서 나중에(아래쪽에) 배치된 SET/RESET 명령이 최종 상태를 결정합니다.

Q3. 같은 출력을 여러 개의 일반 코일로 중복 사용할 때 생기는 문제를 무엇이라 부르는가?

💡 해설: 같은 출력을 여러 네트워크에서 일반 코일로 중복 사용하는 것을 다중 코일 할당이라 하며, 예상치 못한 동작을 유발할 수 있습니다.

Q4. 논리식 전체를 반전시킬 때 사용할 수 있는 것은?

💡 해설: NOT(부정) 표시를 사용하면 이미 만들어진 논리식 전체의 결과를 반전시킬 수 있습니다.

03. 타이머 - TON / TOF / TP

📌 핵심 요약

타이머동작
TON (On-Delay)입력 ON 후 설정시간 경과해야 출력 ON
TOF (Off-Delay)입력 OFF 후 설정시간 경과해야 출력 OFF (입력 켜지면 출력은 즉시 ON)
TP (Pulse)입력 ON되는 순간 설정시간만큼만 출력 ON, 이후 자동 OFF

1. 시간 데이터 타입(Time)

타이머의 설정시간(PT)에는 보통 Time이라는 전용 데이터 타입을 사용하며, T#5S(5초), T#1H(1시간)처럼 시간 단위를 붙여서 입력한다.

2. 경과시간(ET) 활용

타이머에는 설정시간(PT) 외에 경과시간(ET, Elapsed Time) 출력도 있어, 현재 얼마나 시간이 지났는지 실시간으로 확인하거나 다른 로직에서 활용할 수 있다.

3. IEC 타이머 vs S7 타이머

TIA Portal에서는 데이터 타입 기반의 IEC 타이머(TON, TOF, TP)를 사용하는 것이 표준이며, 예전 S7 방식의 S5Time 기반 타이머(예: S_ODT)는 STEP 7 Classic과의 호환을 위해 남아있는 경우가 있다. 새 프로젝트는 IEC 타이머 사용을 권장한다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 입력이 꺼진 후 설정시간이 지나야 출력이 꺼지는 타이머는?

💡 해설: TOF(Off-Delay Timer)는 입력이 꺼진 뒤 설정시간이 지나야 출력이 꺼집니다.

Q2. 입력이 켜지는 순간 설정시간만큼만 출력이 켜지고 자동으로 꺼지는 타이머는?

💡 해설: TP(Pulse Timer)는 입력이 켜지는 순간부터 설정시간만큼만 출력이 켜지고 이후 자동으로 꺼집니다.

Q3. 타이머의 설정시간(PT)에 흔히 사용하는 데이터 타입은?

💡 해설: 타이머의 설정시간(PT)에는 Time이라는 전용 데이터 타입을 사용해 T#5S와 같이 입력합니다.

Q4. 현재 타이머가 얼마나 시간이 지났는지 확인할 수 있는 출력은?

💡 해설: ET(Elapsed Time, 경과시간)는 타이머가 시작된 이후 현재까지 지난 시간을 나타냅니다.

04. 카운터 - CTU / CTD / CTUD

📌 핵심 요약

카운터동작
CTU (Up Counter)CU 입력마다 1씩 증가, 설정값(PV) 도달시 출력 ON
CTD (Down Counter)CD 입력마다 1씩 감소, 0이 되면 출력 ON
CTUD증가·감소를 모두 지원하는 업다운 카운터
세 가지 모두 R(리셋) 입력으로 현재값을 초기화한다.

1. 카운터의 데이터 타입

카운터의 현재값(CV)과 설정값(PV)은 보통 Int 또는 다른 정수형으로 지정하며, 사용하려는 카운트 범위(음수 여부, 최대값)에 맞춰 적절한 정수 타입을 선택해야 한다.

2. 입력 신호의 순간 감지(Edge)

카운터의 CU/CD 입력은 신호가 계속 1로 유지되는 동안 계속 세는 것이 아니라, 0에서 1로 바뀌는 순간(상승 엣지)마다 한 번씩만 카운트된다. 그래서 센서 신호가 짧게 깜빡여야 정확히 개수를 셀 수 있다.

3. CTUD의 응용

CTUD는 입고(CU)와 출고(CD)를 동시에 관리해야 하는 재고 카운트 같은 상황에서 유용하다. 예를 들어 창고에 물건이 들어오면 CU, 나가면 CD를 눌러 현재 재고량을 실시간으로 추적할 수 있다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 카운트 값이 설정값에서부터 감소하여 0이 되면 출력이 ON되는 카운터는?

💡 해설: CTD(Down Counter)는 CD 입력마다 값이 감소하여 0이 되면 출력이 ON됩니다.

Q2. 증가와 감소를 모두 지원하는 카운터는?

💡 해설: CTUD는 업(증가)과 다운(감소)을 모두 지원하는 업다운 카운터입니다.

Q3. 카운터의 CU 입력이 실제로 카운트를 증가시키는 시점은?

💡 해설: CU 입력은 상승 엣지(0→1로 바뀌는 순간)마다 한 번씩만 카운트를 증가시킵니다.

Q4. 입고와 출고를 동시에 관리해야 하는 재고 카운트에 적합한 카운터는?

💡 해설: CTUD는 증가(CU)와 감소(CD)를 모두 지원하므로 입출고를 함께 관리하는 재고 카운트에 적합합니다.

05. 비교 명령 (CMP)

1. 비교 연산자

연산자의미
==같다
<>다르다
>, <크다, 작다
>=, <=크거나 같다, 작거나 같다
두 값을 비교해 참/거짓 접점처럼 사용할 수 있다.

2. 주의사항

비교하려는 두 값의 데이터 타입이 일치해야 한다(예: Int와 Real을 그대로 비교하면 오류가 날 수 있음).

3. 범위 판정 만들기

특정 값이 일정 범위 안에 있는지 확인하려면, '값 >= 하한' 조건과 '값 <= 상한' 조건 두 개의 CMP를 직렬(AND)로 연결하면 된다. 예를 들어 온도가 20~30도 사이인지 확인할 때 자주 쓰이는 패턴이다.

4. 실무 활용 예

탱크의 수위 센서 값(아날로그, IW 형태)을 CMP로 상한선과 비교해 일정 값을 넘으면 경보를 울리는 등, 비교 명령은 아날로그 신호를 감시하는 데 특히 자주 사용된다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 두 값이 서로 다른지 비교하는 연산자는?

💡 해설: <>는 두 값이 서로 다른지를 비교하는 연산자입니다.

Q2. 비교 명령을 사용할 때 반드시 확인해야 하는 것은?

💡 해설: 비교하려는 두 값의 데이터 타입이 일치해야 정상적으로 비교됩니다.

Q3. 값이 일정 범위 안에 있는지 확인하려면 어떻게 구성하는가?

💡 해설: 하한 이상, 상한 이하라는 두 조건을 직렬(AND)로 연결하면 값이 범위 안에 있는지 확인할 수 있습니다.

Q4. 탱크 수위가 일정 값을 넘으면 경보를 울리는 로직에 주로 사용되는 명령은?

💡 해설: 아날로그 신호를 상한값과 비교해 경보를 발생시키는 데 CMP(비교) 명령이 자주 사용됩니다.

06. 이동·연산 명령 (MOVE, ADD 등)

1. MOVE

한 주소의 값을 다른 주소로 그대로 복사하는 명령이다.

2. 사칙연산 명령

ADD(덧셈), SUB(뺄셈), MUL(곱셈), DIV(나눗셈) 명령으로 두 값을 계산해 결과를 다른 주소에 저장할 수 있다.

3. 데이터 타입 일치

연산에 사용하는 값들도 서로 같은 데이터 타입이어야 하며, 다르면 타입 변환 명령(CONVERT)을 먼저 거쳐야 한다.

4. 실무 활용 - 아날로그 값 스케일링

센서에서 들어오는 아날로그 원시값(예: 0~27648)을 실제 물리량(예: 0~100도)으로 변환할 때, SUB/MUL/DIV를 조합한 스케일링 계산식을 직접 만들어 사용하는 경우가 많다. 일부 CPU/펌웨어에서는 이런 변환을 대신해주는 전용 명령(NORM_X, SCALE_X)을 제공하기도 한다.

5. 자주 하는 실수

정수(Int) 나눗셈에서는 소수점 이하가 버림 처리된다는 점을 놓쳐서 계산 결과가 예상과 다르게 나오는 경우가 흔하다. 소수점이 필요한 계산이라면 처음부터 Real 타입으로 변환해서 계산하는 것이 안전하다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 한 주소의 값을 다른 주소로 복사하는 명령은?

💡 해설: MOVE 명령은 한 주소의 값을 다른 주소로 그대로 복사합니다.

Q2. 두 값을 더하는 연산 명령은?

💡 해설: ADD는 두 값을 더하는 사칙연산 명령입니다.

Q3. 아날로그 원시값을 실제 물리량으로 변환하는 작업을 무엇이라 부르는가?

💡 해설: 아날로그 원시값을 실제 물리량 단위로 바꾸는 계산을 스케일링이라 부릅니다.

Q4. 정수(Int) 타입끼리 나눗셈을 할 때 흔히 발생하는 문제는?

💡 해설: 정수 나눗셈은 소수점 이하를 버리기 때문에, 소수점이 필요한 계산은 Real 타입으로 먼저 변환해야 합니다.

07. 데이터 타입 (Bool/Byte/Int/DInt/Real)

📌 핵심 요약

타입설명
Bool0 또는 1(참/거짓) 1비트
Byte8비트
Int16비트 정수
DInt32비트 정수
Real32비트 실수(소수점 포함)

1. 각 타입의 표현 범위

Int는 대략 -32768 ~ 32767 범위를 표현할 수 있고, 이보다 큰 값을 다뤄야 한다면 DInt(더 넓은 정수 범위)를 사용해야 한다. 범위를 넘어서는 값을 Int에 넣으면 오버플로우(값이 예상과 다르게 튀는 현상)가 발생할 수 있다.

2. 문자열(String)과 구조체(Struct)

기본 타입 외에도 텍스트를 저장하는 String, 여러 변수를 하나로 묶는 구조체(Struct, User Data Type)도 자주 사용된다. 예를 들어 한 제품의 '이름, 수량, 가격'을 묶어 하나의 구조체로 관리하면 데이터 관리가 편해진다.

3. 타입 변환 (CONVERT)

서로 다른 데이터 타입끼리 계산하거나 비교해야 할 때는 CONVERT 명령으로 타입을 먼저 맞춰야 한다. 예를 들어 Int 값을 Real로 변환한 뒤 소수점 계산에 사용하는 식이다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 0 또는 1 두 가지 값만 가지는 가장 기본적인 데이터 타입은?

💡 해설: Bool은 0(거짓) 또는 1(참) 두 가지 값만 가지는 가장 기본적인 데이터 타입입니다.

Q2. 소수점이 있는 값을 저장할 때 사용하는 데이터 타입은?

💡 해설: Real은 소수점을 포함한 실수 값을 저장하는 데이터 타입입니다.

Q3. Int 타입의 표현 범위를 넘어서는 값을 넣었을 때 발생할 수 있는 문제는?

💡 해설: Int의 표현 범위를 넘는 값을 넣으면 오버플로우가 발생해 값이 예상과 다르게 나타날 수 있습니다.

Q4. 서로 다른 데이터 타입끼리 계산하기 전에 타입을 맞추는 명령은?

💡 해설: CONVERT 명령으로 데이터 타입을 변환한 뒤 계산이나 비교를 수행해야 정확한 결과를 얻을 수 있습니다.

08. 프로그램 구조 (OB1/FC/FB/DB 활용)

1. 왜 블록을 나누는가

하나의 거대한 OB1 대신 기능별로 여러 개의 FC/FB로 나누어 프로그램을 구성하면 가독성이 좋아지고, 비슷한 로직을 다른 프로젝트에서도 재사용하기 쉬워진다.

2. 호출 구조

보통 OB1에서 필요한 FC/FB들을 순서대로 호출(Call)하는 형태로 프로그램을 구성한다.

3. 인스턴스 DB

FB를 호출할 때는 그 상태를 저장할 인스턴스 DB를 함께 지정해야 하며, 이 DB 덕분에 FB는 다음 스캔에서도 이전 상태(예: 타이머 경과시간)를 기억할 수 있다.

4. 매개변수(입출력) 설계

FC/FB를 만들 때는 Input(입력), Output(출력), InOut(입출력), Static(내부 저장용) 매개변수를 적절히 설계해야 한다. 예를 들어 '모터 제어' FB라면 기동/정지 버튼을 Input으로, 모터 출력을 Output으로 받도록 설계할 수 있다.

5. 명명 규칙(Naming Convention) 정하기

블록 개수가 많아질수록 FC/FB/DB 이름에 일관된 규칙(예: FC_모터제어, FB_컨베이어, DB_설정값)을 정해두면, 나중에 필요한 블록을 프로젝트 트리에서 빠르게 찾을 수 있어 유지보수가 쉬워진다.
✏️ 단원 확인문제 (4문제)
점수: 0 / 100점 (정답 0 / 4문제)

Q1. 여러 개의 FC/FB로 나누어 프로그램을 구성하는 주된 이유는?

💡 해설: 기능별로 블록을 나누면 프로그램의 가독성이 좋아지고 다른 프로젝트에서도 재사용하기 쉬워집니다.

Q2. FB를 호출할 때 그 상태(값)를 저장하기 위해 함께 사용하는 블록은?

💡 해설: FB 호출시 인스턴스 DB를 함께 지정하여 다음 스캔에서도 상태를 기억할 수 있습니다.

Q3. FC/FB를 설계할 때 기동·정지 버튼처럼 밖에서 안으로 들어오는 값에 사용하는 매개변수 종류는?

💡 해설: 밖에서 블록 안으로 들어오는 값은 Input(입력) 매개변수로 설계합니다.

Q4. 블록이 많아질 때 유지보수를 쉽게 하기 위한 방법은?

💡 해설: FC/FB/DB에 일관된 명명 규칙을 사용하면 필요한 블록을 빠르게 찾을 수 있어 유지보수가 쉬워집니다.
